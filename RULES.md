# Правила проекта

Эти правила сформированы из плана выполнения тестового задания «сервис форм» для FutureToday и обязательны при любой доработке кода.

## Запуск и зависимость от окружения

1. Проект обязан запускаться двумя командами из корня: `npm install` и `npm start`. Любое изменение, ломающее эту последовательность, недопустимо.
2. Единственная зависимость — `express`. Новые npm-пакеты добавляются только по веской причине; запрещены: сборщики (webpack/Vite), нативные модули, anything, требующий API-ключей, сети или отдельно установленной СУБД.
3. Порт — только из `process.env.PORT` (fallback 3000). Хардкод порта запрещён.
4. Админка и публичные формы обслуживаются одним процессом на одном порту. Два сервера или проксирование между ними запрещены.
5. Поддерживается Node.js 20+: не использовать синтаксис и API, появившиеся позже.

## Хранилище данных

6. Данные живут в `data/db.json`. Файл создаётся автоматически при первом запуске, если отсутствует.
7. Запись — только через `server/db.js`: атомарно (временный файл + rename) и с отложенным flush. Прямой `fs` для данных в роутах запрещён.
8. Схема данных расширяется только обратно совместимо: старый `db.json` должен продолжать открываться.

## Маршруты и безопасность

9. `/admin` доступен без авторизации (требование ТЗ). Авторизацию, роли и токены не добавлять.
10. Публичная форма доступна только в статусе `published`. Черновик по `/f/:slug` отдаёт сообщение «недоступна»; просмотр черновика — только через `?preview=1` из админки.
11. Всё, что пришло от пользователя (названия, label, help, варианты, ответы), вставляется в DOM исключительно через `textContent`/`createElement`. `innerHTML` с пользовательскими данными запрещён.
12. Ответы валидируются и на клиенте, и на сервере. Сервер не доверяет клиенту: типы, email, числа, даты и варианты из списка проверяются заново в `server/validate.js`.
13. JSON-парсер ограничен по размеру тела запроса. Ошибки валидации возвращаются как `{ error: 'текст' }` со статусом 4xx, внутренние — 500 без стека наружу.

## Фронтенд

14. Без сборки: ванильный HTML/CSS/JS. Запрещено добавлять фреймворки и этапы сборки.
15. Админка состоит из трёх страниц (список форм, билдер, ответы). Разделение обязанностей и имена файлов сохраняются.
16. Общие запросы к API — только через `public/admin/api.js` (единая обработка ошибок).
17. Интерфейс на русском языке, тексты — в разметке или в JS-константах, без «умных» строк от API.

## Аналитика

18. События — только `view`, `start`, `abandon`, `submit` (тип фиксирован в `TRACK_TYPES`). Новые типы — отдельным решением.
19. `sessionId` берётся из sessionStorage и не содержит персональных данных студентов.
20. Предпросмотр из админки (`?preview=1`) не должен писать события в статистику.

## CSV-экспорт

21. Экспорт отдаётся с `Content-Disposition: attachment`, BOM `\uFEFF` для Excel, экранированием кавычек и защитой ячеек от формул (значения, начинающиеся с `=`, `+`, `-`, `@`).

## Данные и демо

22. `data/db.json` в git не коммитится — он в `.gitignore`. Файл создаётся приложением автоматически, демо-данные генерирует `server/seed.js`, а не захардкоженный JSON.
23. `AI_LOG.md` — обязательная часть сдачи: не удалять, дополнять при существенных изменениях.

## Процесс

24. Коммиты не делать без явного подтверждения пользователя: сначала изменения в рабочем дереве, потом ревью пользователем, потом коммит.
25. Перед сдачей прогоняется приёмочный чек-лист из README: чистый запуск, публикация, отправка, воронка, CSV, XSS-вектор, недоступность черновика.
