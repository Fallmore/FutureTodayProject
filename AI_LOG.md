# Лог работы с AI

Задание: тестовое «сервис форм» для компании FutureToday (конструктор форм отклика).
Инструмент: OpenCode (AI-ассистент) + MiMo-V2.6.

---

## Этап 1. Разбор ТЗ и выбор архитектуры

Прочитано техническое задание из `ТЗ Младший веб-разработчик.docx`. Ключевые ограничения: Node.js ≥ 20, запуск ровно двумя командами `npm install` → `npm start`, порт через env `PORT`, админка `/admin` без авторизации, данные внутри проекта, никаких внешних сервисов, лог AI не удалять.

Проанализированы проблемы из ТЗ: (1) менеджеры ждут форму от разработчиков по несколько дней; (2) причина низкой конверсии заполнения форм неизвестна. Вторая проблема закрыта аналитикой воронки — она напрямую отвечает на неё.

Рассмотрены варианты архитектуры:
- **A. Express + ванильный JS + JSON-файл** — выбран: ноль сборки, максимальная надёжность запуска, один процесс/один порт;
- B. Express + React/Vite — отклонён: сборка в `postinstall` добавляет время и риск для проверки;
- C. Next.js — отклонён: требует `build` перед `start`, тяжёлое дерево зависимостей;
- D. чистый `node:http` — отклонён: вручную писать роутинг и парсинг body нерационально.

Хранилище: JSON-файл (`data/db.json`) с атомарной записью temp+rename и отложенным flush — нулевой риск нативной сборки, проверяющий всегда запустит проект.

## Этап 2. Схема данных и сервер

Спроектирована модель: `forms` (схема полей, статус draft/published, slug), `submissions` (ответы по id полей), `events` (view/start/abandon/submit для воронки).
Реализовано:
- `server/db.js` — хранилище с атомарной записью и дебаунсом, автосоздание файла с демо-данными;
- `server/validate.js` — единая валидация: схемы формы (админка) и ответов студента (сервер не доверяет клиенту: проверяет типы, email, число, дату, варианты из списка);
- `server/ids.js` — uuid, короткие id полей, slug с транслитерацией;
- `server/routes/apiAdmin.js` — CRUD форм, publish/unpublish, ответы, CSV-экспорт (BOM для Excel, экранирование кавычек, защита от формул);
- `server/routes/publicForm.js` — публичная схема, приём ответов, трекинг событий;
- `server/index.js` — Express, статика, JSON-парсер с лимитом, обработка 404 и ошибок, PORT из env.

## Этап 3. Админка

Три отдельные страницы без сборки (каждая тривиально читается):
- `index.html` + `app.js` — список форм с карточками, статистикой, публикацией, копированием ссылки, удалением с подтверждением;
- `edit.html` + `builder.js` — билдер: 8 типов вопросов, обязательность, подсказки, варианты ответов, порядок (↑/↓), диалог редактирования, предпросмотр, Ctrl+S, предупреждение при уходе с несохранёнными изменениями;
- `responses.html` + `responses.js` — воронка (просмотры → начали → отправили + конверсия), подсказка «где бросают», таблица заполнения/бросаний по полям, таблица ответов, кнопка CSV.

Весь пользовательский контент вставляется через `textContent` — защита от XSS в админке.

## Этап 4. Публичная форма

`public/form/index.html` + `form.js` + `form.css`: рендер из JSON-схемы, клиентская валидация (те же правила, что на сервере), подсветка ошибок, состояния «загрузка / недоступна / успех», трекинг view/start/abandon через `sendBeacon` с `sessionId` в sessionStorage. Предпросмотр (`?preview=1`) не пишет статистику. Все элементы создаются через `createElement`/`textContent` — XSS невозможен.

## Этап 5. Демо-данные и проверка

`server/seed.js`: опубликованная форма «Стажировка Backend-разработчик, лето 2026» с 8 вопросами всех типов, черновик воркшопа, 6 ответов, 14 просмотров / 11 начали / 6 отправили — воронка и таблица бросаний выглядят наглядно сразу после запуска.

Выполнен прогон приёмки: запуск с чистого `npm install`, порт через `PORT`, публикация, отправка ответа, блокировка пустого обязательного поля, CSV с кириллицей, XSS-вектор в label отображается как текст, черновик недоступен по публичной ссылке.

## Принятые решения (итог)

1. Архитектура — вариант A: монолит Express, ванильный фронтенд, JSON-хранилище.
2. В объём включены: аналитика воронки с точкой выпадения и экспорт ответов в CSV.
3. Авторизация, загрузка файлов, мультистеп, email — сознательно не реализуются (не требуется ТЗ, приоритет — продуманность).
